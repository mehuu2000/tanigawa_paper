# 改修方針: 誤植あり正例データの再生成と比較実験

## 背景

現在の予備実験・評価実験では、誤植なしの正例データを使用して閾値取得とシステム評価を行っている。

過去には誤植あり正例データを使用した実験も行っているが、その後、以下のような修正が加えられた。

- MongoDB / Solr を Crossref なしの JaLC データだけで再構築した。
- 正例・負例から Crossref 由来データを除外した。
- `title` と `subtitle` の結合方法を修正した。
- 英語著者名の空白や日本語著者判定を修正した。
- Solr の `creator` / `first_author` 登録内容を修正した。
- トークン化時の先頭数字削除処理を削除した。
- `creator` から英語著者のイニシャル派生表記を削除した。
- MC を RC と CC の F0.5 として計算するように修正した。

そのため、過去の誤植あり正例データは、現在のデータ集合・整形処理・検索環境と条件が一致していない。

今回、現在の誤植なし正例と同じ論文集合・同じ整形処理を使って誤植あり正例を再生成し、誤植なし条件と比較する。

## 目的

以下の2条件を、現在の同一システム上で比較する。

- 誤植なし正例を使った閾値取得・評価
- 誤植あり正例を使った閾値取得・評価

確認する内容:

- 誤植によって各スコアリング方式の閾値がどのように変化するか。
- 正例の正常検出・検出漏れ・誤検出がどの程度変化するか。
- 負例の誤検出がどの程度変化するか。
- BM25 / BM25正規化 / RC / CC / MC のうち、どの方式が誤植の影響を受けやすいか。
- 誤植あり正例に最適化した閾値を使った場合でも、誤植なし条件との差が残るか。

## 基本方針

- 現在の誤植なし正例データは変更しない。
- 過去の誤植あり正例データも変更しない。
- 誤植あり正例は新しいnotebookと別ディレクトリで作成する。
- 現在の誤植なし正例と同じDOIリストを使用する。
- DOIの件数と行順を維持する。
- 現在の3引用スタイルの整形処理をそのまま使用する。
- 誤植付与には固定シードを使用し、同じデータを再生成できるようにする。
- 予備実験用と評価実験用の両方を作成する。
- 負例データは誤植なし条件で使用したものをそのまま使用する。
- Solr登録データは変更しないため、Solrの削除・再登録は行わない。

## 誤植付与方式

過去の誤植付与方式を維持する。

### 誤植を含む確率

- 各参考文献文字列に対して35%
- JSAI / IPSJ / LSJごとに独立して判定する

### 誤植数

誤植付与対象となった参考文献について:

- 誤植1つ: 80%
- 誤植2つ: 20%

### 誤植対象

| 対象 | 内容 | 選択確率 |
|---|---|---:|
| タイトル | ランダムな1文字を削除 | 40% |
| 著者 | 最後の著者1名を削除 | 20% |
| 雑誌名 | ランダムな1文字を削除 | 15% |
| 出版年 | 数値を±1 | 5% |
| 巻 | 数値を±1 | 5% |
| 号 | 数値を±1 | 5% |
| 頁 | 先頭頁または末尾頁を±1 | 10% |

数値でない巻・号・頁などが選択された場合は、過去実装と同じ分岐に従う。

## 再現性の確保

固定シードは`4プログラム/config.py`で一元管理する。

```python
REFERENCE_TYPO_SEED = 20260719
```

単一のグローバル乱数列には依存せず、以下の組み合わせから安定した乱数を生成する。

- 固定シード
- データセット種別: `pre` / `eval`
- 引用スタイル: `jsai` / `ipsj` / `lsj`
- DOI

これにより、以下の場合でも同じDOI・同じスタイルには同じ誤植が付与される。

- Cellの実行順が変わった場合
- 予備実験用と評価実験用を別々に実行した場合
- notebookを再起動して再実行した場合

## データ生成時の検証

誤植ありデータを書き出す前に、以下を確認する。

1. DOIリストを使ってMongoDBから現在の整形処理で誤植なし文字列を再生成する。
2. 再生成結果と既存の誤植なし正例をスタイルごとに全行比較する。
3. 全行一致した場合のみ誤植あり正例を書き出す。
4. MongoDB未登録・日本語条件不一致・学術会議登録団体条件不一致が1件でもあれば出力せず停止する。
5. DOI件数と行順が入力DOIリストから変わっていないことを確認する。

出力ログには以下を含める。

- 入力DOI数
- 生成件数
- スキップ件数と対象DOI
- 誤植付与対象数
- 実際に1箇所以上変化した参考文献数
- 誤植種類別の要求数と実際の変化数

`typo_manifest_*.jsonl`には、DOI・スタイルごとの誤植選択結果と操作内容を保存する。

## 再実験手順

### Step 1: 誤植あり正例データの生成

`create_references_typo_crossref.ipynb`を実行し、予備実験用・評価実験用の誤植あり正例を生成する。

### Step 2: 生成結果の確認

以下を確認する。

- 予備実験用が各701件である。
- 評価実験用が各843件である。
- DOIリストの件数と行順が誤植なし条件と一致する。
- スキップが0件である。
- 誤植なし再生成結果が既存データと完全一致する。
- 同じシードで再実行した場合に出力が変わらない。

### Step 3: 閾値の再取得

対象:

- `4プログラム/preliminary_experiment.ipynb`

正例入力を予備実験用の誤植あり正例へ切り替える。

負例は現在のものをそのまま使用する。

再取得対象:

- BM25
- BM25正規化
- RC
- CC
- MC

### Step 4: `config.py`への反映

誤植あり条件で取得した閾値を`4プログラム/config.py`へ反映する。

誤植なし条件の閾値は、過去セットとしてまとまったコメントブロックに残す。

`SOLR_DOC_COUNT`と`SOLR_CORE_NAME`はSolr環境を変更しないため、そのまま維持する。

### Step 5: システム再評価

対象:

- `4プログラム/evaluation_experiment.ipynb`

正例入力を評価実験用の誤植あり正例へ切り替える。

評価対象:

- 正例3スタイル
- 負例3スタイル
- BM25
- BM25正規化
- RC
- CC
- MC

正例のDOIは、誤植あり評価実験用ディレクトリの`doi_list.txt`を使用する。

負例は誤植なし条件と同じものを使用する。

### Step 6: 誤植なし条件との比較

以下を比較する。

- 各指標の閾値
- 正例の`case1`
- 正例の`case2 + case4`
- 正例の`case3`
- 負例のTrue negative
- 負例のFalse positive

正例は3スタイル合算2529件、負例は3スタイル合算2397件を母数として割合を求める。

- 誤植なし再生成結果が既存データと完全一致している。

- 既存の誤植なし正例と過去の誤植あり正例を変更していない。

- 新しい閾値を`config.py`へ反映している。
- 誤植あり正例・既存負例を使った再評価が完了している。
