# 改修方針: 誤植あり正例データの再生成と比較実験

## 背景

現在の予備実験・評価実験では、誤植なしの正例データを使用して閾値取得とシステム評価を行っている。

過去には誤植あり正例データを使用した実験も行っているが、その後、以下のような修正が加えられた。

- MongoDB / Solr を Crossref なしの JaLC データだけで再構築した。
- 正例・負例から Crossref 由来データを除外した。
- `title` と `subtitle` の結合方法を修正した。
- 英語著者名の空白や日本語著者判定を修正した。
- Solr の `creator` / `first_author` 登録内容を修正した。
- トークン化時の先頭数字削除処理を削除した。
- `creator` から英語著者のイニシャル派生表記を削除した。
- MC を RC と CC の F0.5 として計算するように修正した。

そのため、過去の誤植あり正例データは、現在のデータ集合・整形処理・検索環境と条件が一致していない。

今回、現在の誤植なし正例と同じ論文集合・同じ整形処理を使って誤植あり正例を再生成し、誤植なし条件と比較する。

## 目的

以下の2条件を、現在の同一システム上で比較する。

- 誤植なし正例を使った閾値取得・評価
- 誤植あり正例を使った閾値取得・評価

確認する内容:

- 誤植によって各スコアリング方式の閾値がどのように変化するか。
- 正例の正常検出・検出漏れ・誤検出がどの程度変化するか。
- 負例の誤検出がどの程度変化するか。
- BM25 / BM25正規化 / RC / CC / MC のうち、どの方式が誤植の影響を受けやすいか。
- 誤植あり正例に最適化した閾値を使った場合でも、誤植なし条件との差が残るか。

## 基本方針

- 現在の誤植なし正例データは変更しない。
- 過去の誤植あり正例データも変更しない。
- 誤植あり正例は新しいnotebookと別ディレクトリで作成する。
- 現在の誤植なし正例と同じDOIリストを使用する。
- DOIの件数と行順を維持する。
- 現在の3引用スタイルの整形処理をそのまま使用する。
- 誤植付与には固定シードを使用し、同じデータを再生成できるようにする。
- 予備実験用と評価実験用の両方を作成する。
- 負例データは誤植なし条件で使用したものをそのまま使用する。
- Solr登録データは変更しないため、Solrの削除・再登録は行わない。

## 誤植付与方式

過去の誤植付与方式を維持する。

### 誤植を含む確率

- 各参考文献文字列に対して35%
- JSAI / IPSJ / LSJごとに独立して判定する

### 誤植数

誤植付与対象となった参考文献について:

- 誤植1つ: 80%
- 誤植2つ: 20%

### 誤植対象

| 対象 | 内容 | 選択確率 |
|---|---|---:|
| タイトル | ランダムな1文字を削除 | 40% |
| 著者 | 最後の著者1名を削除 | 20% |
| 雑誌名 | ランダムな1文字を削除 | 15% |
| 出版年 | 数値を±1 | 5% |
| 巻 | 数値を±1 | 5% |
| 号 | 数値を±1 | 5% |
| 頁 | 先頭頁または末尾頁を±1 | 10% |

数値でない巻・号・頁などが選択された場合は、過去実装と同じ分岐に従う。

## 再現性の確保

固定シードは`4プログラム/config.py`で一元管理する。

```python
REFERENCE_TYPO_SEED = 20260719
```

単一のグローバル乱数列には依存せず、以下の組み合わせから安定した乱数を生成する。

- 固定シード
- データセット種別: `pre` / `eval`
- 引用スタイル: `jsai` / `ipsj` / `lsj`
- DOI

これにより、以下の場合でも同じDOI・同じスタイルには同じ誤植が付与される。

- Cellの実行順が変わった場合
- 予備実験用と評価実験用を別々に実行した場合
- notebookを再起動して再実行した場合

## データ生成時の検証

誤植ありデータを書き出す前に、以下を確認する。

1. DOIリストを使ってMongoDBから現在の整形処理で誤植なし文字列を再生成する。
2. 再生成結果と既存の誤植なし正例をスタイルごとに全行比較する。
3. 全行一致した場合のみ誤植あり正例を書き出す。
4. MongoDB未登録・日本語条件不一致・学術会議登録団体条件不一致が1件でもあれば出力せず停止する。
5. DOI件数と行順が入力DOIリストから変わっていないことを確認する。

出力ログには以下を含める。

- 入力DOI数
- 生成件数
- スキップ件数と対象DOI
- 誤植付与対象数
- 実際に1箇所以上変化した参考文献数
- 誤植種類別の要求数と実際の変化数

`typo_manifest_*.jsonl`には、DOI・スタイルごとの誤植選択結果と操作内容を保存する。

## 追加方針: イニシャル登録あり・なしの比較

誤植あり正例の評価では、Solrの`creator`に英語著者のイニシャル派生表記を登録しない条件だけでなく、イニシャル派生表記を登録する条件でも実験する。

### 比較する条件

| 条件 | 正例データ | Solr `creator`のイニシャル派生表記 |
|---|---|---|
| A | 誤植なし | あり |
| B | 誤植なし | なし |
| C | 誤植あり | あり |
| D | 誤植あり | なし |

既存結果との対応:

- 条件A: `progress5/進捗_パーフェクト.md`
- 条件B: `progress5/進捗_イニシャル.md`
- 条件C: 今後実施する誤植あり・イニシャルあり条件
- 条件D: 今回先に実施する誤植あり・イニシャルなし条件

### イニシャルの定義

イニシャルあり・なしは、参考文献文字列の表記ではなく、Solrの`creator`に追加する派生値を指す。

イニシャルなし:

- `creator`に`T`、`A`、`J`、`JM`などの人工的なイニシャル派生値を登録しない。
- IPSJ / JSAIの参考文献文字列には、引用形式として`Nontachai, T.`のようなイニシャル表記が含まれる。
- LSJは`Nontachai TITHIPONGTRAKUL`のようなフルネーム表記を使用する。

イニシャルあり:

- 英語著者の`first_name`から、1文字または2文字のイニシャル順列を生成して`creator`へ追加する。
- 正例参考文献文字列自体はイニシャルなし条件と同じものを使う。

### 実施順序

#### Phase 1: 誤植あり・イニシャルなし

現在の環境をそのまま使用する。

- Solrは現在登録済みのイニシャルなしデータを使用する。
- 予備実験用の誤植あり正例と既存負例から取得した閾値を使用する。
- 評価実験用の誤植あり正例と既存負例を再評価する。
- Solr再登録は不要である。

#### Phase 2: 誤植あり・イニシャルあり

Phase 1完了後に実施する。

1. `4プログラム/jalc-to-solr.ipynb`の`get_creator()`へイニシャル生成処理だけを復元する。
2. それ以外の`creator`、`first_author`、`title subtitle`、空白著者除外などの処理は変更しない。
3. Solrを全件削除し、同じJaLCデータを再登録してcommitする。
4. `numFound`と代表的な英語著者の`creator`を確認する。
5. 同じ予備実験用誤植あり正例・同じ負例で5指標の閾値を再取得する。
6. イニシャルあり条件の閾値を`config.py`へ反映する。
7. 同じ評価実験用誤植あり正例・同じ負例で再評価する。

### 比較時の注意

- イニシャル有無でSolr登録内容が変わるため、それぞれの環境で閾値を再取得する。
- 条件Cと条件Dでは、正例・負例・DOI・誤植内容・固定シードを同一にする。
- イニシャルあり条件となし条件で、誤植あり正例を再生成しない。
- `typo_manifest_pre.jsonl`と`typo_manifest_eval.jsonl`も同じものを使用する。
- 負例データも同じものを使用する。
- Solr登録件数が変化しない場合でも、登録フィールド値が変わるため再登録と閾値再取得は必要である。

### 追加の完了条件

- 誤植あり・イニシャルなし条件の正例・負例評価が完了している。
- 誤植あり・イニシャルあり条件でSolr再登録と閾値再取得が完了している。
- 誤植あり・イニシャルあり条件の正例・負例評価が完了している。
- 4条件について閾値と評価結果を比較できる。
- RC / CC / MCに対する誤植とイニシャル登録の影響を分離して説明できる。
