# 改修方針: データ登録・正例データ作成

## 背景

英語著者を含む文献において、Solr に登録している著者表記と、正例データとして作成している参考文献文字列側の著者表記が一致していない可能性がある。

特に LSJ 形式の正例データでは、英語著者も日本語著者と同じように `last_name + first_name` で空白なし連結している。

例:

```text
Nontachai + TITHIPONGTRAKUL
=> NontachaiTITHIPONGTRAKUL
```

一方で、Solr 側には英語著者の空白なしフルネームは登録されていない。

そのため、英語著者を含む文献では、RC / CC / MC の著者部分の一致が不安定になる可能性がある。

## 改修目的

英語著者の表記を、Solr 登録側と正例データ作成側で揃える。

具体的には、英語著者の空白ありフルネーム `last_name first_name` を扱えるようにする。

例:

```text
Nontachai TITHIPONGTRAKUL
Adnan AKMAL
```

## 改修内容

### 1. Solr 登録側: `creator` の修正

対象:

- `4プログラム/jalc-to-solr.ipynb`

現在の `creator` では、英語著者に対して主に以下を登録している。

| 種類 | 例 |
|---|---|
| `last_name` | `Nontachai` |
| `first_name` | `TITHIPONGTRAKUL` |
| `first_name` 由来のイニシャル | `T` |

改修後は、これに加えて空白ありフルネームを登録する。

| 追加するもの | 例 |
|---|---|
| `last_name first_name` | `Nontachai TITHIPONGTRAKUL` |

想定する修正:

```python
if last_name and first_name:
    creator_list.append(last_name + " " + first_name)
```

ただし、日本語著者の既存挙動を壊さないように、英語著者または非日本語著者に対して追加する。

### 2. Solr 登録側: `first_author` の修正

対象:

- `4プログラム/jalc-to-solr.ipynb`

現在の `first_author` では、英語筆頭著者は基本的に `last_name` のみを登録している。

例:

```text
Nontachai
```

改修後は、英語筆頭著者に対して以下も登録する。

| 追加するもの | 例 |
|---|---|
| `first_name` | `TITHIPONGTRAKUL` |
| `last_name first_name` | `Nontachai TITHIPONGTRAKUL` |

CC は `first_author` を利用するため、ここを増やすことで英語著者の CC が安定しやすくなる。

### 3. 正例データ作成側: LSJ の英語著者表記の修正

対象:

- `4プログラム/create_references_none_typo_crossref.ipynb`
- 必要に応じて、同系統の正例データ作成 notebook

現在の LSJ 形式では、言語判定なしで以下のように著者名を作成している。

```python
for name in creator_list:
    tmp.append(name[0] + name[1])
```

そのため、英語著者も空白なしで連結される。

例:

```text
NontachaiTITHIPONGTRAKUL
AdnanAKMAL
```

改修後は、英語著者または非日本語著者の場合は空白ありで作成する。

例:

```text
Nontachai TITHIPONGTRAKUL
Adnan AKMAL
```

日本語著者については、従来通り `last_name + first_name` を維持する。

想定する分岐:

```python
if has_japanese(name[0]):
    tmp.append(name[0] + name[1])
else:
    tmp.append(name[0] + " " + name[1])
```

ただし、`last_name` が空の場合なども考慮し、既存データで破綻しない形にする。

### 4. Solr 登録側: title / subtitle 結合方法の修正

対象:

- `4プログラム/jalc-to-solr.ipynb`

現在の Solr 登録側では、`subtitle` がある場合に `title + " | " + subtitle` を登録している。

```python
title_list.append(t.get("title"))
if (subtitle := t.get("subtitle")) is not None:
    title_list.append(t.get("title") + " | " + subtitle)
```

一方、正例データ作成側では、`subtitle` がある場合に `title + " " + subtitle` として参考文献文字列を作成している。

```python
title_text = title
if subtitle != "":
    title_text = title_text + " " + subtitle
```

そのため、`subtitle` がある文献では Solr 側と正例データ側のタイトル表記がずれる。

日本語タイトルでは、`title subtitle` の境界部分にも文字 2-gram が生成される一方、`title | subtitle` では `|` が区切り文字として扱われるため、境界部分のトークンが一致しない。

改修後は、Solr 登録側を正例データ作成側に合わせる。

```python
title_list.append(t.get("title"))
if (subtitle := t.get("subtitle")) is not None:
    title_list.append(t.get("title") + " " + subtitle)
```

`title` 単体の登録は維持する。

これにより、`subtitle` なしの文献では従来どおり `title` のみが使われ、`subtitle` ありの文献では正例データ側と同じ `title subtitle` 表記を Solr 側にも持たせる。

## 改修後に必要な作業

### 1. Solr 再登録

Solr 登録ロジックを変更するため、既存の Solr データを削除し、再登録する必要がある。

目的:

- `title` に `title subtitle` 形式を登録し、正例データ側のタイトル表記と揃える。

LSJ 形式の参考文献文字列生成ロジックを変更するため、正例データを再作成する必要がある。

## 注意点

JSAI / IPSJ の英語著者表記は `Nontachai, T.` のような形式である。

この形式は `wakati.get_token()` により、概ね以下のようにトークン化される。

```text
Nontachai, T.
=> nontachai, t
```

Solr 側には `Nontachai` と `T` が登録されているため、JSAI / IPSJ については LSJ ほど大きな不一致は起きにくい。

今回の主な問題は、LSJ 形式で英語著者が `NontachaiTITHIPONGTRAKUL` のように空白なし連結され、Solr 側の登録表記と噛み合わない点である。

## 負例データの修正方針

負例データについては、MongoDB から再生成しない方針とする。

理由は、負例データの作成時に Gemini が生成したタイトル一覧をインデックスで参照しているためである。

評価用負例では、`eval_experiment_titles.txt` と `llm_create_titles.txt` が同じインデックスで対応している。

```text
eval_experiment_titles[0] に対応する架空タイトル = llm_create_titles[0]
eval_experiment_titles[1] に対応する架空タイトル = llm_create_titles[1]
...
```

負例作成コードでは、MongoDB を `find(query)` で走査し、条件に合った文献ごとに `count` を進めて `llm_create_titles[count]` を参照している。

```python
documents = mycol.find(query)
count = 0

for doc in documents:
    if check_lang(doc) and check_publisher(doc, scj_registered_AcademicSocieties):
        llm_create_title = llm_create_titles[count]
        ...
        count += 1
```

この処理は MongoDB の走査順に依存している。

`find(query)` に `sort` が指定されていないため、MongoDB の再構築やインデックス変更後に同じ順序で文献を取得できるとは限らない。

そのため、負例を再生成すると、元タイトルと Gemini 生成タイトルの対応がずれる可能性がある。

### 方針

既存の負例ファイルを維持したまま、LSJ 形式の英語著者の空白なし連結だけを補正する。

対象ファイル:

- `5データ/5-1予備実験用データ/5-1-2参考文献文字列（架空）/negative_reference_lsj_pre.txt`
- `5データ/5-2評価実験用データ/5-2-2参考文献文字列（架空）/negative_reference_lsj_eval.txt`

JSAI / IPSJ は、英語著者が `Nontachai, T.` のような形式であり、トークン化後も `nontachai`, `t` として扱われるため、基本的には修正対象外とする。

### 修正対象

LSJ 形式は以下のような構造である。

```text
著者1・著者2・...（年）「タイトル」『学会名』
```

修正対象は、`（年）` より前の著者部分のみとする。

タイトル、学会名、年、行順、件数は変更しない。

### 修正例

```text
NontachaiTITHIPONGTRAKUL
=> Nontachai TITHIPONGTRAKUL

CLANUWATTarin
=> CLANUWAT Tarin

LAMBAlex
=> LAMB Alex

AyiguliAINI
=> Ayiguli AINI
```

### 作業方針

恒久的な変換スクリプトは作成しない。

負例データは Gemini 生成タイトルとの対応関係を壊さないことが重要であるため、既存ファイルを維持したまま、Codex が一回限りの作業として LSJ 負例ファイルを直接確認・補正する。

英字連結は機械的に安全に分割できるとは限らないため、単純な正規表現による一括分割は避ける。

Codex が既存の LSJ 負例ファイルから英字連結候補を抽出し、置換対象を確認した上で、対応表ベースで該当箇所のみを直接修正する。

作業時の流れ:

1. Codex が LSJ 負例ファイルから、著者部分に含まれる英字連結候補を抽出する。
2. Codex が抽出結果を確認し、`置換前 -> 置換後` の対応表を整理する。
3. Codex が対応表に一致する著者表記だけをファイル上で直接置換する。
4. Codex が置換前後の差分を確認する。
5. Codex が行数と行順が変わっていないことを確認する。
6. ユーザーが最終的な修正結果を確認する。

### 完了条件

- LSJ 負例データ内の英語著者の空白なし連結が、空白あり表記に補正されていること。
- JSAI / IPSJ の負例データは変更していないこと。
- 負例データの行数と行順が変わっていないこと。
- Gemini 生成タイトルとの対応関係を壊していないこと。
