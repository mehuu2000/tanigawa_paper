# 負例データ Crossref 由来行の削除候補

## 目的

現在の負例データは、Crossref データを含んでいた時点のデータを元に作成されている。

そのため、Crossref を除いた JaLC のみの環境に合わせるため、負例データから Crossref 由来の行を削除する候補を確認する。

この時点では削除は行わず、削除候補の確認のみを行う。

## 判定方針

負例データには DOI が直接含まれていない。

そのため、以下の手順で DOI を復元して削除候補を判定する。

1. 旧 `doi_list.txt` と Crossref なし `doi_list.txt` を比較し、Crossref 由来として削除された DOI を特定する。
2. 負例データの各行から Gemini 生成タイトルを抽出する。
3. 抽出したタイトルを `llm_create_titles.txt` または `llm_create_titles_2.txt` の順序に沿って対応付ける。
4. 対応した行番号から旧 `doi_list.txt` の DOI を復元する。
5. 復元した DOI が Crossref なし `doi_list.txt` に存在しない場合、その負例行を削除候補とする。
6. JSAI / IPSJ / LSJ は同じループで同時に生成されているため、削除する場合は3スタイルで同じ行番号を同時に削除する。

## 注意点

- 負例データ内には DOI がないため、負例ファイル単体では DOI 差分判定はできない。
- `llm_create_titles` には重複タイトルがあるため、単純なタイトル辞書ではなく、行順に沿って対応付ける必要がある。
- LSJ は `「...」` 形式の中にタイトル由来の引用符が含まれる場合があり、単純な正規表現では一部タイトル抽出に失敗する。
- ただし JSAI / IPSJ は全行対応できており、JSAI / IPSJ / LSJ は同じ行順で生成されているため、削除候補行は JSAI / IPSJ の復元結果を基準にする。

## 削除する場合の操作

削除する場合は、以下の行を JSAI / IPSJ / LSJ の3ファイルから同時に削除する。

- 予備実験用負例: 1〜10行目
- 評価実験用負例: 1〜19行目

削除後に確認すること:

- 予備実験用負例が各500件になること。
- 評価実験用負例が各799件になること。
- JSAI / IPSJ / LSJ の行数が一致していること。
- JSAI / IPSJ / LSJ の行順が崩れていないこと。
