# 問題確認

## 調査対象

- `4プログラム/jalc-to-solr.ipynb`
- `4プログラム/create_references.ipynb`
- `4プログラム/create_references_none_typo.ipynb`
- `4プログラム/create_references_none_typo_crossref.ipynb`

## 確認した問題

Solr に登録している著者表記と、正例データとして作成している参考文献文字列側の著者表記が、特に英語著者で一致していない可能性が高い。

そのため、英語著者を含む文献では、検索後の RC / CC / MC の類似度計算時に著者部分のトークン一致が低下する可能性がある。

## Solr 登録側の英語著者表記

`jalc-to-solr.ipynb` では、著者情報は主に `creator` と `first_author` に登録される。

### `creator`

英語著者の場合、以下のような表記が登録される。

| 登録されるもの | 例 |
|---|---|
| `last_name` | `Nontachai` |
| `first_name` | `TITHIPONGTRAKUL` |
| `first_name` を分割した各要素 | `TITHIPONGTRAKUL` |
| `first_name` 由来のイニシャル | `T` |
| 複数語 first_name の場合のイニシャル順列 | `A`, `H`, `AH`, `HA` など |

一方で、以下のような完成形の英語著者表記は登録されていない。

| 登録されないもの | 例 |
|---|---|
| 空白ありのフルネーム | `Nontachai TITHIPONGTRAKUL` |
| 空白なしのフルネーム | `NontachaiTITHIPONGTRAKUL` |
| カンマ + イニシャル表記 | `Nontachai, T.` |

### `first_author`

英語筆頭著者の場合、基本的には `last_name` のみが登録される。

| 登録されるもの | 例 |
|---|---|
| `last_name` | `Nontachai` |

`first_author` にも、以下のような表記は登録されていない。

| 登録されないもの | 例 |
|---|---|
| 空白ありのフルネーム | `Nontachai TITHIPONGTRAKUL` |
| 空白なしのフルネーム | `NontachaiTITHIPONGTRAKUL` |
| カンマ + イニシャル表記 | `Nontachai, T.` |

## 正例データ作成側の英語著者表記

正例データ作成側では、MongoDB の `creator_list[*].names` から `[last_name, first_name]` を取り出し、それを各引用スタイルに変換している。

英語著者の表記は、スタイルごとに異なる。

| 引用スタイル | 実装上の作り方 | 例 |
|---|---|---|
| JSAI | `last_name + ", " + first_name[0] + "."` | `Nontachai, T.` |
| IPSJ | `last_name + ", " + first_name[0] + "."` | `Nontachai, T.` |
| LSJ | `last_name + first_name` | `NontachaiTITHIPONGTRAKUL` |

特に LSJ では、言語判定なしで以下のように連結している。

```python
for name in creator_list:
    tmp.append(name[0] + name[1])
```

そのため、日本語著者では `山田太郎` のように自然な表記になるが、英語著者では `NontachaiTITHIPONGTRAKUL` や `AdnanAKMAL` のように空白なしで連結される。

## 比較

`Nontachai` / `TITHIPONGTRAKUL` を例にすると、Solr 登録側と正例データ側は以下のようにずれている。

| 場所 | 表記 |
|---|---|
| Solr `creator` | `Nontachai`, `TITHIPONGTRAKUL`, `T` |
| Solr `first_author` | `Nontachai` |
| JSAI 正例 | `Nontachai, T.` |
| IPSJ 正例 | `Nontachai, T.` |
| LSJ 正例 | `NontachaiTITHIPONGTRAKUL` |

このため、正例データ側に出てくる `Nontachai, T.` や `NontachaiTITHIPONGTRAKUL` は、Solr 側にそのままの形では登録されていない。

## RC / CC / MC への影響

RC は、参考文献文字列側のトークンが候補文献メタデータ側にどれだけ含まれるかを見る指標である。

```text
RC = 共通トークン数 / 参考文献文字列側のユニークトークン数
```

そのため、正例データ側の英語著者表記と Solr 側の英語著者表記が一致しない場合、著者部分の共通トークンが減り、RC が下がる可能性がある。

CC は、候補文献メタデータ側の各フィールドが参考文献文字列側にどれだけ含まれるかを見る指標である。

そのため、`first_author` に `Nontachai` しか登録されていない一方で、参考文献文字列側が `NontachaiTITHIPONGTRAKUL` のような連結表記になっている場合、著者フィールドの一致が不安定になる可能性がある。

MC は RC と CC を合成した指標であるため、英語著者表記のずれは MC にも影響する。

## 現時点の結論

英語著者を含む文献でスコアが落ちる原因の一つとして、Solr 登録側と正例データ作成側の著者表記の不一致が考えられる。

特に LSJ 形式では、英語著者を `last_name + first_name` で空白なし連結しているため、Solr 側の登録表記と噛み合っていない。

次に修正する場合は、少なくとも以下のどちらか、または両方を検討する必要がある。

- 正例データ作成側の LSJ 英語著者表記を、`last_name + " " + first_name` のように空白ありへ修正する。
- Solr 登録側にも、英語著者の空白ありフルネームや引用スタイル用表記を追加する。

## 追加確認: title / subtitle の不一致

著者表記以外に、タイトルとサブタイトルの結合方法にも不一致がある。

Solr 登録側では、`subtitle` がある場合に `title + " | " + subtitle` を登録している。

```python
title_list.append(t.get("title"))
if (subtitle := t.get("subtitle")) is not None:
    title_list.append(t.get("title") + " | " + subtitle)
```

一方、正例データ作成側では、`subtitle` がある場合に `title + " " + subtitle` として参考文献文字列を作成している。

```python
title_text = title
if subtitle != "":
    title_text = title_text + " " + subtitle
```

比較すると以下のようになる。

| ケース | Solr 登録側 | 正例データ作成側 |
|---|---|---|
| `subtitle` なし | `title` | `title` |
| `subtitle` あり | `title` と `title \| subtitle` | `title subtitle` |

`subtitle` がない場合は、Solr 側も正例データ側も `title` のみになるため不一致は起きにくい。

しかし、`subtitle` がある場合は、Solr 側と正例データ側で表記が確実にずれる。

日本語タイトルでは `wakati.py` が文字 2-gram を生成するため、正例データ側の `title subtitle` では「タイトル末尾 + サブタイトル先頭」をまたぐ 2-gram が生成される。

一方、Solr 側の `title | subtitle` では `|` が区切り文字として扱われるため、この境界 2-gram が生成されない。

そのため、`subtitle` を持つ文献では RC が下がる可能性がある。

### 対応方針

正例データ作成側は変更せず、Solr 登録側を正例データ側に合わせる。

具体的には、Solr 登録時の `get_title()` で `title + " | " + subtitle` ではなく、`title + " " + subtitle` を登録する。

```python
title_list.append(t.get("title"))
if (subtitle := t.get("subtitle")) is not None:
    title_list.append(t.get("title") + " " + subtitle)
```

`title` 単体の登録は維持するため、`subtitle` なしの文献や、タイトル単体での検索には影響しにくい。
