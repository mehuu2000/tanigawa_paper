# 進捗: creator からイニシャルを削除した再実験

## 目的

`progress5/改修方針_イニシャル.md` に基づき、Solr の `creator` から英語著者のイニシャル派生表記を削除し、閾値再取得とシステム再評価を行う。

この実験は、パーフェクト条件の後に行う比較実験である。

確認したいこと:

- イニシャル派生表記がない場合に、RC / MC がどの程度影響を受けるか。
- 参考文献文字列側に存在するイニシャル表記が候補文献側にない場合、RC が低下することを確認できるか。
- パーフェクト条件との差分を説明できるか。

## 前提

この実験は、以下が完了した後に行う。

- `progress5/改修方針_パーフェクト.md` の実装。

### 閾値結果

| 指標 | 閾値 |
|---|---:|
| BM25 | 40.988663 |
| BM25正規化 | 1.7602185714285714 |
| RC | 1.0 |
| CC | 1.0 |
| MC | 0.9887005649717513 |

備考:

- RC はイニシャル削除の影響を受けており、予備実験用正例 2103件のうち 9件はスコアが 1.0 未満になった。
- 代表例として、`CLANUWAT, T.，LAMB, A.，KITAMOTO, A.` や `Simon, G.` のような英語著者イニシャル表記を含む参考文献では、候補文献側 `creator` から `T` / `A` / `G` などの派生イニシャルを削除したため、RC が低下した。
- ただし、負例側にも RC スコア 1.0 のものが 3件あり、さらに 0.98 台の高スコア負例も存在した。
- 閾値決定は正例最小値ではなく、`roc_curve` の候補閾値ごとに F1 を計算し、F1 が最大になる閾値を採用している。
- そのため、閾値を 1.0 未満に下げて 9件の正例を拾うより、閾値 1.0 のままにして高スコア負例の誤検出を抑える方が F1 が高くなり、RC の Best Threshold は 1.0 になった。
- MC は RC の低下を受け、正例最小値に相当する `0.9887005649717513` が Best Threshold になった。
